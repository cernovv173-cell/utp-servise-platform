# ЕНОТ СЕРВИС — Android

В версии 1.5.30 при регистрации клиента обязателен корректный номер телефона. Клиенты без номера, включая вход через VK ID, сначала заполняют телефон и только после этого открывают личный кабинет. В дополнительных разделах доступны чаты по заявкам для клиентов, мастеров и администратора, а также три памятки для клиентов. В чаты можно вставлять смайлики из панели рядом с полем сообщения. В Android-разделе администратора «Управление» доступны акции и розыгрыши, баннеры с фото и просмотр бонусных балансов и операций.

Карточки всех заявок в Android-списках — активных, завершённых и архивных — открываются в компактном виде: номер, устройство, статус и краткое описание. Нажатие «Открыть подробности заявки» раскрывает остальную информацию и действия. В подробной карточке показываются услуги и запчасти из общего каталога с количеством, ценой и суммой. Администратор может пополнять прайс, редактировать и отключать позиции; мастер выбирает активные позиции только для назначенных ему заказов. Сервер фиксирует цену при добавлении, а уже оформленные строки сохраняются при изменении прайса. В каталоге запчастей администратор задаёт и корректирует остаток, мастер видит его при выборе, а позиция с нулевым остатком недоступна для добавления. При добавлении запчасти к заказу остаток списывается на сервере; при удалении строки или отмене заявки возвращается. Для каждой запчасти и товара администратор может задать собственный минимальный остаток; при достижении порога Android показывает сигнал пополнения и включает позицию в быстрый фильтр. Нулевой остаток отмечается всегда, а порог 0 означает сигнал только при нуле. Новые позиции по умолчанию получают порог 3; услуги, скрытые позиции и товары без учёта остатка не включаются в сводку. Для старых позиций без записанного начального остатка сначала внесите фактическое количество.

Администратор может редактировать данные активного или завершённого заказа. В активной заявке он может удалить услугу, запчасть или товар; если позиция связана со складом, её количество возвращается в остаток. В завершённом заказе позиции можно удалить через редактирование неоплаченного чека, установив количество 0; сервер удалит строку, вернёт связанный остаток и пересчитает итог, бонусную скидку и зарплату. Оплаченный чек остаётся без изменений.

Администратор редактирует чек каждого завершённого заказа отдельно из его карточки: меняет количества услуг и запчастей, добавляет одну позицию «Свободная продажа» (товар или услуга, название, количество и цена) и пересохраняет неоплаченный чек. Сервер одновременно обновляет состав заказа, бонусную скидку и расчёт мастера; оплаченный чек нельзя менять. Список заявок остаётся общим, а состав и чек управляются в отдельном заказе.

Главная клиента в Android после входа показывает приветствие, основную кнопку заявки, быстрые ссылки на ремонты, магазин, бонусы и новости, а также одну карточку текущего ремонта. Главная мастера показывает число активных и срочных назначений, быстрые переходы к заказам, каталогу, зарплате и профилю, затем ближайший ремонт. Главная администратора показывает актуальные счётчики заявок и ремонтов, быстрые переходы к расписанию, клиентам и управлению, а также ближайшую задачу. Счётчики и карточки строятся по загруженным заявкам, без демонстрационных цифр. В верхней шапке для всех ролей есть кнопка с шестерёнкой «Все разделы»: она открывает только дополнительные экраны, доступные текущей роли, а нижняя навигация остаётся для частых разделов. Администратор может создавать черновики новостей, редактировать их, публиковать и снимать с публикации. Клиенты и мастера не получают черновики.

Администратор может задать для новости начало и окончание публикации по местному времени устройства и отметить её приоритетной. Сервер показывает новость обычным пользователям только внутри заданного интервала и возвращает приоритетные новости первыми; административный список сохраняет доступ к черновикам и публикациям вне срока.

В разделе «Новости и отзывы» Android и Web показывается общая подборка фактов о технологиях со ссылкой на первоисточник. Клиенты передают API идентификатор последнего факта и сохраняют новый: Web — в `sessionStorage`, Android — в `SharedPreferences`. При перезагрузке страницы или следующем открытии приложения показывается другой факт; автоматическое обновление карточки раз в два часа сохранено.

В разделе «Новости и отзывы» приоритетные новости и рекламные баннеры показываются каруселями: каждый материал сменяется через 10 секунд с плавным горизонтальным переходом. При нескольких публикациях клиент может листать их вручную или поставить автоматическую смену на паузу; полный список новостей и отзывов остаётся обычным списком.

Публичные главные страницы Web и Android используют одну короткую последовательность: заявка, услуги, шаги ремонта, один опубликованный отзыв и контакты. Отзывы берутся только из публичной выдачи завершённых ремонтов; стоимость показывается только если она задана в сервисе, без выдуманных цен. На главной Android есть кнопка звонка, открывающая номер компании; в блоке контактов сохранены отдельные входы клиента и сотрудников.

На публичной главной Android и в разделе «Акции и розыгрыши» крупными карточками показываются опубликованные предложения только в период их проведения. Список обновляется примерно раз в 30 секунд, срок дополнительно проверяется на устройстве; переход ведёт к условиям и участию. Для загрузки карточек используется публичная выдача API без данных участников и победителей.

В настройках профиля доступны темы «Как в системе», светлая и тёмная. Выбор хранится на устройстве и применяется после перезапуска приложения.

Администратор может перемещать кнопку «СТАРТ / СТОП — Создать заявку» долгим нажатием и перетаскиванием;
положение сохраняется на устройстве для его учётной записи. Скрыть или вернуть кнопку и сбросить её
положение в правый нижний угол можно в разделе «Управление → Настройки приложения». Там же
доступна информация о версии программы.

Клиент может дополнительно указать пол и дату рождения в профиле — оба поля необязательны. Если дата сохранена и на устройстве разрешены push-уведомления, в день рождения придёт персональное поздравление от ЕНОТа. Мастер и администратор эти поля не видят.

В программе лояльности 1 балл даёт 1 ₽ скидки, но баллы не являются деньгами и не переводятся и не выводятся. После подтверждённой денежной оплаты ремонта начисляется 10%, заказного изделия — 5%. Ранее начисленные игровые баллы остаются на бонусных балансах клиентов; награды за прежние игровые механики больше не выдаются. Отдельные опубликованные розыгрыши могут начислять только явно указанные администратором бонусные баллы. При выдаче ремонта мастер или администратор может выбрать списание баллов: не больше доступного остатка и 30% стоимости строк «Услуга». Запчасти, товары и изделия бонусами не оплачиваются; профилактическая работа подходит, если добавлена в заказ как услуга.

В программе лояльности клиенту выдаются три личных одноразовых кода приглашения сроком на шесть месяцев. Код можно указать при регистрации в Android или Web; после первого завершённого и оплаченного ремонта нового клиента по 250 бонусных баллов начисляется и ему, и пригласившему. Регистрация сама по себе награду не выдаёт. В карточке видны сроки и статусы кодов, а поделиться можно каждым ещё доступным кодом. Баллы остаются личными, не переводятся и не обналичиваются.

Раздел «Рукоделия» доступен клиенту во вкладке магазина и администратору в управлении. Опубликованные готовые изделия показываются на вкладке «Рукоделие» и могут попасть в одну корзину с обычными товарами; сервер проверяет остаток при подтверждении заказа, уменьшает его один раз, а при отмене возвращает. Изделия без остатка не продаются как готовые. Индивидуальное изготовление остаётся отдельной заявкой: администратор обсуждает пожелания, назначает активного мастера и согласует цену и срок. В каждой заявке есть отдельный чат клиента с администратором: можно отправлять текст и фотографии, а после статуса «В работе» переписка автоматически открывается внутри карточки заказа. Фото доступны только участникам чата этой заявки. Перед завершением администратор назначает активного мастера и цену; при завершении автоматически создаются чек и сервисный номер, а зарплата мастера рассчитывается по его сохранённой индивидуальной ставке. Заказные изделия бонусами не оплачиваются: администратор может списать бонусы только за услуги ремонта, максимум 30% их стоимости. Онлайн-оплата не подключена: заявка остаётся запросом, а подтверждение оплаты фиксирует уже полученный платёж.

Раздел «О компании» доступен клиентам и мастерам из дополнительных ссылок профиля, а администраторам — из управления сервисом. Администратор может изменить общие сведения о компании в Android-приложении или веб-панели; клиенты и мастера видят описание, историю, услуги, контакты, график, соцсети, реквизиты и добавленные ссылки на фото и видео.

В карточке заказа клиент и назначенный мастер могут открыть сохранённый чат. Мастер может передать вопрос администратору; запрос появится в разделе управления, администратор подключится к беседе и сможет ответить. Чат клиента с администратором проверяет новые сообщения каждые 3 секунды, список клиентских чатов администратора — каждые 5 секунд; время каждого сообщения показывается по часовому поясу устройства. Android принимает push о сообщениях и запросах помощи, изменениях заказа (включая назначение, статус, состав, расчёт, фото и отзывы), запросе отзыва мастером, первой публикации новости и поздравлениях с днём рождения; нажатие на запрос отзыва открывает форму по нужной заявке. Публикация акции или розыгрыша уведомляет клиентов при начале срока проведения; статусы «Готов к выдаче» и успешная выдача техники получают отдельные понятные уведомления. Сервер уведомляет участников заказа, кроме автора действия; новости и предложения рассылаются клиентам. Для обычных уведомлений используется фирменный звук «Мягкая искра», а для победы в розыгрыше — отдельный праздничный вариант. Приложение создаёт системные каналы `repair_updates_soft_spark` и `repair_winner_soft_spark`; сервер отправляет победителям уведомление с Android channel ID `repair_winner_soft_spark`, остальные сообщения идут в `repair_updates_soft_spark`. Пользователь может изменить звук или отключить уведомления каждого канала в настройках Android. Для доставки нужны Firebase-настройки, зарегистрированный токен устройства и разрешение на уведомления.

Приложение проверяет наличие новой версии на сайте при открытии и возвращении на экран. Если в панели администратора загружен APK с более высоким номером сборки, приложение показывает предложение обновиться. После нажатия оно скачивает APK по HTTPS, сверяет SHA-256, package name и версию, затем открывает системный установщик Android. Если потребуется, пользователь разрешает установку APK из ЕНОТ СЕРВИС в настройках устройства. Android отдельно проверяет подпись приложения и требует подтвердить установку; обновление не устанавливается скрытно. Администратор указывает в панели название и номер сборки, совпадающие с загруженным APK. Старые установленные версии без этой проверки сначала нужно обновить обычным способом.

Удаление строк заказа, онлайн-оплата и публикация APK в Google Play в текущую версию не входят.

Нативное приложение на Kotlin и Jetpack Compose для ремонта компьютеров, ноутбуков и моноблоков. Название приложения — ЕНОТ СЕРВИС. Идентификатор пакета `ru.utp.servise` сохранён для совместимости обновлений.

## Реализованные сценарии

- Отдельные порталы входа клиента, мастера и администратора. Публичная регистрация создаёт только клиента и требует корректный номер телефона; выбрать себе роль сотрудника нельзя. Если клиент вошёл через VK ID или восстановил старый аккаунт без номера, личный кабинет остаётся закрытым до сохранения телефона.
- На экране входа клиент, мастер или администратор может запросить код восстановления по электронной почте или короткому логину. Код отправляется на привязанную почту и/или в МАКС; ссылку из сообщения можно открыть на веб-экране восстановления и подтвердить код тем же логином или адресом.
- На экранах входа и регистрации клиента доступен вход через бота МАКС: приложение получает одноразовую ссылку `https://max.ru/<botName>?start=<payload>`, открывает её, а затем каждые две секунды проверяет подтверждение. В чате бот просит поделиться контактом; сервер проверяет подпись контакта и находит или создаёт клиента по номеру телефона. При регистрации бот отправляет «Спасибо что выбрали нас!». Пароль не нужен, новый аккаунт создаётся только в роли клиента, а код приглашения применяется при создании. Сотрудники по-прежнему входят по почте и паролю. Вход через Яндекс ID удалён.
- Клиент с аккаунтом MAX может в профиле добавить резервную почту: запросить код, подтвердить адрес и задать пароль. Только после подтверждения можно войти по почте и паролю; вход через MAX продолжает работать.
- Если настроены `VK_ID_APP_ID` и `VK_ID_CLIENT_SECRET`, на экране входа доступен VK ID. Приложение запрашивает email, отправляет полученный VK access token в `POST /api/auth/vk`, а сервер сам проверяет его у VK ID. Новый аккаунт создаётся только для клиента; привязка к существующей почте требует её пароль. Существующие способы входа не заменяются.
- Клиент создаёт заявку, видит только собственные заказы и историю, может отменить только новую заявку и оставить один отзыв после завершения ремонта.
- В «Все разделы → Ремонты и техника → Кабинет компании» клиент может указать название организации, вести отдельный список её техники, создавать заявки компании и открывать их в общем списке документов ремонта. Сервер отделяет личную технику и заявки и проверяет выбранную технику компании. Старые личные записи остаются личными; профиль не проверяет юридический статус, не поддерживает сотрудников и не формирует отдельные бухгалтерские документы.
- В профиле клиент может начать удаление аккаунта прямо в Android-приложении. Перед подтверждением показывается предупреждение об удалении заявок, заказов, переписок, фото и бонусов; после успеха очищается локальная корзина, а при временной ошибке очистки сессию можно использовать для повторной попытки.
- Магазин клиента объединяет обычные товары и опубликованные готовые изделия ручной работы в одной корзине; для рукоделия показывается остаток, а заказное изготовление по-прежнему оформляется отдельной заявкой. Нажатие «Подробнее» открывает отдельную карточку товара или изделия с фотографиями, описанием, ценой, наличием и добавлением в эту же корзину. При нехватке учтённого остатка приложение просит уменьшить количество и не создаёт заказ; для позиций без учёта остатка наличие вручную проверяет администратор. Клиент может отменить свой ожидающий заказ на самовывоз до подтверждения; курьерский заказ можно отменить отказом от предложенных условий доставки. Клиент также может выбрать курьера по Пушкино и ближайшему Подмосковью. Цена и срок доставки не вычисляются автоматически: администратор вручную предлагает их, клиент принимает предложение или отказывается до подтверждения заказа. Доставка изделия на заказ обсуждается после его готовности. Администратор открывает очередь заказов магазина из управления, проверяет наличие до подтверждения (в этот момент списывается учтённый остаток), а затем отмечает заказ выданным или отменяет его; при отмене подтверждённого заказа остаток возвращается. Онлайн-оплата и внешняя служба доставки не подключены; оплату и получение согласуют отдельно.
- После завершения ремонта клиент видит в карточке заказа поздравление енота, краткий итог работ и условия выданной гарантии. Кнопка открывает существующую форму отзыва; повторный отзыв не предлагается. Назначенный мастер в завершённом заказе может один раз запросить отзыв; клиенту отправляется push с переходом к этой форме, а при недоставке push просьба остаётся видна в заказе. Рядом есть отдельная кнопка «Отправить чаевые»; пока она сообщает, что приём платежей станет доступен после регистрации и настройки ЮMoney, и не запускает оплату.
- Игровая функция и её API удалены из Android и Web. Первая новая версия очищает прежний WebView-кэш и локальные игровые отметки; аккаунты, корзина и уже начисленные бонусные баллы сохраняются. Игровые таблицы удаляются миграцией базы данных, а записи `GAME_REWARD` в журнале бонусов остаются.
- Нижняя панель клиента содержит «Главная», «Ремонты», «Магазин», «Чат» и «Профиль»; «Бонусы» доступны через шестерёнку «Все разделы». Панель мастера содержит «Заказы», «Каталог», «Зарплата» и «Профиль»; закупки и администратор используют короткие панели из трёх и четырёх пунктов соответственно. История завершённых заявок доступна из фильтра списка ремонтов. Дополнительные экраны каждой роли открываются через шестерёнку «Все разделы» в верхней шапке; переходы остаются ограничены правами текущей роли и сохраняют выделение подходящей вкладки нижней панели.
- В новой заявке клиент может указать марку, модель и серийный номер техники, добавить фото и выбрать желаемое время. Время предварительное: сервис подтверждает его после проверки расписания; выбранное фото привязывается к созданной заявке.
- После первичного приёма и назначения мастер ведёт заказ сам — и в сервисном центре, и на выезде. Он готовит смету и дополнительные работы из активного каталога, звонит клиенту и фиксирует в приложении его согласие или отказ; участие администратора в согласовании не требуется. Только после телефонного согласия списываются запчасти со склада и разрешается продолжить ремонт. В акте мастер отмечает фактически выполненные работы и запчасти, затем после звонка фиксирует ответ клиента; до согласия не меняются склад, чек или начисление мастеру. Администратор принимает или создаёт заявку, регистрирует клиента и назначает мастера, но после приёма не подтверждает сметы, акты, готовность, оплату или выдачу. Отметка в приложении подтверждает действие мастера после разговора, а не электронную подпись клиента.
- Для ремонта в сервисном центре мастер заполняет акт состояния и комплектности без обязательных фотографий, согласует смету по телефону, проводит ремонт, отмечает готовность, оформляет оплату и выдачу. На выезде мастер проверяет адрес и расстояние, отмечает проведённую диагностику и выбирает исход после звонка: завершить согласованный ремонт и записать оплату на месте либо получить согласие на перевозку в сервис. После перевозки продолжается тот же сервисный сценарий; приём на месте не считается выдачей. В сервисном центре бонусы списываются только с услуг (1 балл = 1 ₽, максимум 30% стоимости услуг и доступного остатка), не с запчастей, диагностики или километража.
- В акте мастер открывает быстрый каталог с поиском по названию и описанию, фильтрами по типу позиции, избранным и восемью последними добавленными позициями. Списки сохраняются локально для учётной записи на этом устройстве и не синхронизируются с Web. Сохранённые строки меняют склад и чек только после того, как назначенный мастер отметит телефонное согласие клиента.
- Клиент может независимо включать уведомления о ходе ремонта через Telegram и MAX в профиле. Каждая привязка подтверждается одноразовой ссылкой и может быть отключена отдельно; для MAX серверу нужен подключённый токен бота и вебхук.
- Во время новогоднего перерыва на публичном экране и главной клиента показываются объявление и обратный отсчёт. Сервис закрыт с 00:00 по Москве 31 декабря 2026 года по 10 января 2027 года включительно и открывается 11 января в 08:30; таймер обновляется каждую секунду. Если в настройках компании задан телефон, нажатие «Если заказ срочный — звоните» открывает системный набор номера. Баннер скрывается вне периода закрытия.
- В карточке каждой заявки показывается линейный штрихкод Code 128 с сервисным номером. Это только идентификатор заявки; QR-код для выдачи не используется.
- Клиент и сотрудники видят плановую дату готовности и историю переносов с пояснением и автором. После назначения срок может изменить мастер своей заявки; на этапе первичного приёма он доступен администратору. Сервер фиксирует каждое реальное изменение и отправляет клиенту push-уведомление. Для доставки push нужны Firebase-настройки и разрешение на уведомления.
- Администратор создаёт заявку от имени сервиса для существующего или нового клиента и выбирает место ремонта: у клиента или в сервисном центре. Выбор сохраняется отдельно от контактного адреса клиента и показывается в карточке заявки. Для нового клиента указываются имя и телефон; электронная почта необязательна. API создаёт короткий логин из 8 символов и временный пароль; при создании клиента без почты пароль не показывается администратору. Администратор получает ссылку MAX, закреплённую за этой записью клиента; бот отправляет логин и временный пароль только после того, как клиент откроет ссылку и подтвердит свой номер телефона в MAX. Клиент обязан сменить временный пароль при первом входе. Для клиента с электронной почтой логин и временный пароль показываются администратору один раз. Если создание заявки не удалось после регистрации, аккаунт остаётся в базе и заявку можно повторить для этого клиента.
- Незавершённые заявки, в том числе перенесённые на другой срок, остаются в активных до полного завершения ремонта или отмены независимо от даты создания. Выполненные и отменённые заявки переходят в архив на следующий московский календарный день после последнего изменения; архив доступен отдельной вкладкой в списках клиента, мастера и администратора, записи и статусы сохраняются.
- Видео- и GIF-заставка с приветствием отключена: при запуске приложение сразу открывает обычный экран. Приветствие енота в карточке завершённого ремонта сохранено.
- В карточке новой заявки услуги и запчасти ограничены выбранным типом устройства: ПК, ноутбук или моноблок. Программные услуги доступны в отдельной группе «ПО». Для старых заказов сохраняются история и действующие гарантийные обращения; товары магазина остаются отдельными.
- Мастер видит только назначенные ему заказы. В сервисном центре он фиксирует состояние и комплектность устройства без обязательных фото, после телефонного согласования проводит ремонт и сам отмечает готовность, принимает оплату и оформляет выдачу. При выезде мастер проверяет адрес и расстояние, отмечает фактическую диагностику и после звонка либо завершает согласованный ремонт с фиксацией оплаты на месте, либо записывает согласие на перевозку и продолжает заказ в сервисном центре. Приём и перевозка не оформляются как выдача. После оплаты сервер закрывает заказ и создаёт гарантийный талон.
- В карточке заказа доступны акт приёма с описанием состояния, серийным номером, комплектностью и примечаниями, заказ-наряд и выданный гарантийный талон. Для готовности и выдачи в сервисном центре требуется сохранённый акт с заполненным состоянием устройства; вложения не обязательны. Выездной заказ, завершённый на месте, закрывается отдельным сценарием и не требует акта сервисного центра.

## Публикации и примеры работ

Администратор может создать публикацию в формате «Пример работы от сервиса» отдельно от обычной
новости и отзыва клиента. Для истории используются заголовок и описание по схеме «Проблема — что
сделали — результат»; можно загрузить фото, но не видео. Примеры показываются отдельным разделом и
не отправляются как новостные push-уведомления. Старые новости и отзывы остаются без изменений.

## Карточка мастера

Мастер открывает свою анкету из профиля и может редактировать ФИО, телефон, домашний адрес, фото
и стаж. Администратор может просматривать домашний адрес в карточке мастера. Клиенты видят
публичные данные карточки из заказа, но домашний адрес API им не возвращает.

- Мастер видит личную зарплату за день, неделю и месяц; администратор — суммы и индивидуальные ставки всех мастеров. Администратор задаёт процент мастера в Web-разделе «Администрирование → Сотрудники»; по умолчанию действует 75%. Начисление рассчитывается только от стоимости услуг завершённого ремонта, запчасти и товары не учитываются. Применённая ставка сохраняется в начислении, поэтому новая ставка влияет на будущие завершённые заказы, не пересчитывая уже сохранённые суммы; дата начисления — момент завершения заказа.
- Администратор принимает или создаёт заявку, регистрирует клиента и назначает активного мастера; после первичного приёма действия по ремонту, согласованию и выдаче выполняет мастер. Администратор управляет рабочими учётными записями и видит отзывы. В разделе «Управление → Сотрудники → Изменить» администратор может задать индивидуальный процент оплаты каждого мастера (0–100%, по умолчанию 75%). Ставка применяется только к услугам в новых начислениях; запчасти и товары не учитываются, а уже сохранённые начисления не пересчитываются.
- В разделе администратора «Управление» доступны обзор сервиса за 30 дней, недельное расписание выбранного клиентом времени с загрузкой мастеров и закупочная сводка. Рекомендованное количество к заказу доводит остаток до минимального порога; детали из телефонно согласованных смет списываются со склада. Приоритет заявки задаёт администратор на этапе приёма, а после назначения — мастер; это приоритет внимания, а не отдельная гарантия срока.
- Клиент может открыть отдельный чат с администратором из доступного ему раздела поддержки. Администратор получает список клиентских бесед и отвечает из Android-раздела «Управление»; этот чат не зависит от заявки и сохраняет историю сообщений.
- В разделе «База клиентов» администратор ищет клиентов по имени, почте или телефону и редактирует эти контактные данные. Удаление мастера отключает его учётную запись и завершает сессии, но сохраняет историю; при незавершённых назначенных заказах удаление блокируется до их переназначения или завершения.
- Android-раздел «Управление» позволяет создавать новости с фото или видео, публиковать акции и розыгрыши, выбирать победителей розыгрыша, публиковать результаты с начислением предусмотренных баллов, а также создавать баннеры с фото или видео, редактировать, включать и отключать их. Для каждого из трёх призовых мест розыгрыша можно загрузить, заменить или удалить фото приза в формате JPEG, PNG или WebP размером до 5 МБ; клиентам фото доступны только у опубликованных предложений, а у завершённых — после публикации результатов. История баллов доступна только для просмотра. Веб-панель по-прежнему нужна для поиска и сроков заказов и сервисных документов; раздел «О компании» доступен для редактирования и в Android, и в веб-панели.
- Пароли хранятся как scrypt-хеши, токены сессий — только в виде хеша на сервере; токен на Android хранится зашифрованным Android Keystore. Резервное копирование приложения отключено, а приложение запрещает незашифрованный HTTP-трафик.
- Все существенные действия проверяются сервером, а не только скрытием экранов. История статусов хранится в базе.

## Каталог, магазин и бонус ко дню рождения

Карточки обычных товаров и опубликованных готовых изделий доступны в едином каталоге Android-магазина;
обе категории можно положить в одну корзину. Изделие на индивидуальный заказ по-прежнему оформляется
отдельной заявкой. Администратор управляет каталогами и заказами; готовые изделия публикуются только
после ручного указания остатка. Очередь ожидающих подтверждения магазинных заказов вынесена в отдельный
раздел «Подтверждение заказов магазина», а все заказы доступны отдельным фильтром.
Администратор может менять название, описание, цену, остаток и публикацию уже опубликованной карточки
изделия, добавлять и удалять до трёх фотографий или полностью удалить карточку с подтверждением.
Удаление заблокировано при незавершённой заявке на изготовление или ожидающем/подтверждённом заказе;
история завершённых заказов сохраняется. Галереи обычных товаров также ограничены тремя фото.
Доставка для готовых магазинных заказов — самовывоз из Пушкино либо курьер по Пушкино и ближайшему
Подмосковью с ручным согласованием цены и срока администратором; для изделий на заказ её обсуждают
после изготовления. Начисление бонуса ко дню рождения составляет 250 баллов один раз за год и не
зависит от разрешения на push-уведомления.

Администратор может окончательно удалить услугу, запчасть или товар после подтверждения. Для товара
и запчасти сначала требуется указать остаток 0; удалить позицию, используемую в незавершённом ремонте,
ожидающей смете или ожидающем/подтверждённом заказе магазина, нельзя. Завершённые и отменённые заказы
остаются в истории с исходным названием и ценой.

## Старт и вход в приложение

Для неавторизованного пользователя Android сначала показывает короткий приветственный экран, затем — выбор роли: клиент, мастер, закупка или администратор. Выбранная роль открывает соответствующий существующий экран входа; для клиента также доступна регистрация. Способы входа через МАКС, почту/логин и VK ID сохраняются. Полная публичная страница с услугами и контактами доступна с приветственного экрана и выбора роли.

## Сезонное оформление

Приложение получает активную палитру через публичный API и обновляет её примерно раз в минуту.
Администратор открывает «Управление → Сезонное оформление» и нажимает на карточку весны, лета, осени
или зимы; выбор сохраняется на сервере до следующего изменения, одновременно обновляя Web и Android.
Эти же карточки показывают соответствующие сезонные иконки приложения. После сохранения Android
переключает значок на этом устройстве; остальные Android-устройства подхватывают его при следующей
синхронизации, а если приложение было закрыто — при следующем запуске. Кнопка «Вернуть базовую иконку»
отключает сезонный вариант. Выбор не зависит от календарной даты. При включённой теме общий сезонный фон
для сайта и Android показывает фирменного енота:
весной — в лёгком светлом плаще поверх синего костюма, летом — в майке и шортах, осенью — с листьями
в лапах, зимой — в тёплом длинном пальто. Весной движутся лепестки, летом — световые блики, осенью —
листья и дождь длительностью 30 минут раз в час. Зимой дополнительно падают снежинки: 60 на сайте и
24 в Android. На публичной гостевой главной остаётся сезонный баннер; авторизованная главная клиента показывает компактную горизонтальную ленту активных акций и розыгрышей и карточку текущего ремонта, если она есть; фоновые
сцены и баннеры не перекрывают рабочие элементы, а карточки и поля сохраняют контрастные поверхности.

В разделе «Управление → Настройки приложения» администратор может отдельно включать движущуюся цветную
рамку для объявления о перерыве и розыгрышей, а также выбрать собственную палитру для каждого эффекта.
Доступны янтарный, голубой, фиолетовый, розовый, изумрудный и золотой варианты. Настройки хранятся
на сервере и применяются в Android и Web; обычные акции не получают рамку розыгрыша.

## Сборка

```bash
./gradlew :app:assembleDebug --no-daemon --max-workers=2
```

Для обычной сборки требуются JDK 17, Android SDK 36 и HTTPS-переменная `UTP_API_BASE_URL`. APK от `assembleDebug` для разработки не предназначен для публикации. Эмулятор и физическое устройство в среде Amazi недоступны.

Игровых экранов и игровых маршрутов в Android-приложении нет.

Вход через МАКС не требует отдельных переменных в Android-сборке: приложение использует те же HTTPS-адреса `/auth/max/config`, `/auth/max/login` и `/auth/max/login/poll` и открывает чат бота через системный браузер или приложение МАКС. Ссылку и подтверждение формирует сервер, поэтому `MAX_BOT_TOKEN` и секреты вебхука остаются только на API.

### Подписанная сборка для RuStore

Release-вариант подписывается только при заданных переменных `UTP_RELEASE_KEYSTORE_PATH`, `UTP_RELEASE_STORE_PASSWORD`, `UTP_RELEASE_KEY_ALIAS` и `UTP_RELEASE_KEY_PASSWORD`. Задайте их в среде сборки, а `UTP_API_BASE_URL` направьте на HTTPS production API, затем выполните:

```bash
./gradlew :app:assembleRelease --no-daemon --max-workers=2
```

Готовый APK находится в `app/build/outputs/apk/release/`. Файл keystore и пароли — постоянные данные подписи: храните резервную копию в защищённом месте и применяйте ту же подпись при последующих обновлениях. Не добавляйте keystore или пароли в Git. До публикации приложения проверьте, что production API развёрнут и доступен; сборка Android сама API не публикует.

VK ID Android использует официальный SDK `com.vk.id:vkid:2.7.3` из репозитория VK Nexus. В debug-сборке вход через VK можно включать локальными `VK_ID_APP_ID` и `VK_ID_CLIENT_SECRET`. В release эти manifest placeholders и `VK_ID_APP_ID` намеренно очищаются: client secret можно извлечь из распространяемого APK, поэтому вход через VK ID в релизе отключён. Остальные способы входа остаются доступны. Не включайте VK ID в release, пока авторизация не будет переведена на схему без секрета в мобильном клиенте.

Production API доступен на `https://merge.app.amazi.pro`; `/health` отвечает HTTP 200. APK от `assembleDebug` предназначен только для разработки и не годится для публикации.

Чтобы включить push в Android-сборке, задайте `UTP_FIREBASE_ANDROID_CONFIG_JSON` с конфигурацией Firebase Android-приложения `ru.utp.servise`. На API для отправки уведомлений нужна отдельная серверная переменная `FCM_SERVICE_ACCOUNT_JSON`. Если Firebase-конфигурация не задана, Android APK всё равно собирается, но push-доставка недоступна.

## Giveaway rewards

In the offer editor, administrators may configure one, two, or three sequential prize places. The
first place needs a prize description and/or points; later places can be omitted, but a third place
requires a second. Prize photos are optional. Published cards show configured places only, and the
server draws the configured number of giveaway winners.
