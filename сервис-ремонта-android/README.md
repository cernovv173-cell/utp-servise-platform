# ЕНОТ СЕРВИС — Android

В версии 1.5.30 при регистрации клиента обязателен корректный номер телефона. Клиенты без номера, включая вход через VK ID, сначала заполняют телефон и только после этого открывают личный кабинет. В дополнительных разделах доступны чаты по заявкам для клиентов, мастеров и администратора, а также три памятки для клиентов. В чаты можно вставлять смайлики из панели рядом с полем сообщения. В Android-разделе администратора «Управление» доступны акции и розыгрыши, баннеры с фото и просмотр бонусных балансов и операций.

Карточки всех заявок в Android-списках — активных, завершённых и архивных — открываются в компактном виде: номер, устройство, статус и краткое описание. Нажатие «Открыть подробности заявки» раскрывает остальную информацию и действия. В подробной карточке показываются услуги и запчасти из общего каталога с количеством, ценой и суммой. Администратор может пополнять прайс, редактировать и отключать позиции; мастер выбирает активные позиции только для назначенных ему заказов. Сервер фиксирует цену при добавлении, а уже оформленные строки сохраняются при изменении прайса. В каталоге запчастей администратор задаёт и корректирует остаток, мастер видит его при выборе, а позиция с нулевым остатком недоступна для добавления. При добавлении запчасти к заказу остаток списывается на сервере; при удалении строки или отмене заявки возвращается. Для каждой запчасти и товара администратор может задать собственный минимальный остаток; при достижении порога Android показывает сигнал пополнения и включает позицию в быстрый фильтр. Нулевой остаток отмечается всегда, а порог 0 означает сигнал только при нуле. Новые позиции по умолчанию получают порог 3; услуги, скрытые позиции и товары без учёта остатка не включаются в сводку. Для старых позиций без записанного начального остатка сначала внесите фактическое количество.

Администратор может редактировать данные активного или завершённого заказа. В активной заявке он может удалить услугу, запчасть или товар; если позиция связана со складом, её количество возвращается в остаток. В завершённом заказе позиции можно удалить через редактирование неоплаченного чека, установив количество 0; сервер удалит строку, вернёт связанный остаток и пересчитает итог, бонусную скидку и зарплату. Оплаченный чек остаётся без изменений.

Администратор редактирует чек каждого завершённого заказа отдельно из его карточки: меняет количества услуг и запчастей, добавляет одну позицию «Свободная продажа» (товар или услуга, название, количество и цена) и пересохраняет неоплаченный чек. Сервер одновременно обновляет состав заказа, бонусную скидку и расчёт мастера; оплаченный чек нельзя менять. Список заявок остаётся общим, а состав и чек управляются в отдельном заказе.

На клиентской главной отображаются опубликованные новости. Администратор может создавать черновики, редактировать новости, публиковать и снимать их с публикации. Клиенты и мастера не получают черновики.

Администратор может задать для новости начало и окончание публикации по местному времени устройства и отметить её приоритетной. Сервер показывает новость обычным пользователям только внутри заданного интервала и возвращает приоритетные новости первыми; административный список сохраняет доступ к черновикам и публикациям вне срока.

На авторизованной главной Android и в разделе новостей Web показывается общая подборка фактов о технологиях со ссылкой на первоисточник. Клиенты передают API идентификатор последнего факта и сохраняют новый: Web — в `sessionStorage`, Android — в `SharedPreferences`. При перезагрузке страницы или следующем открытии приложения показывается другой факт; автоматическое обновление карточки раз в два часа сохранено.

На главной приоритетные новости и рекламные баннеры на клиентских экранах показываются каруселями: каждый материал сменяется через 10 секунд с плавным горизонтальным переходом. При нескольких публикациях клиент может листать их вручную или поставить автоматическую смену на паузу; полный список новостей и отзывов в разделе новостей остаётся обычным списком.

Публичные главные страницы Web и Android используют одну короткую последовательность: заявка, услуги, шаги ремонта, один опубликованный отзыв и контакты. Отзывы берутся только из публичной выдачи завершённых ремонтов; стоимость показывается только если она задана в сервисе, без выдуманных цен. На главной Android есть кнопка звонка, открывающая номер компании; в блоке контактов сохранены отдельные входы клиента и сотрудников.

На публичной главной Android и на главной клиента крупными карточками показываются опубликованные акции и розыгрыши только в период их проведения. Список обновляется примерно раз в 30 секунд, срок дополнительно проверяется на устройстве; переход ведёт к условиям и участию. Для загрузки карточек используется публичная выдача API без данных участников и победителей.

В настройках профиля доступны темы «Как в системе», светлая и тёмная. Выбор хранится на устройстве и применяется после перезапуска приложения.

Клиент может дополнительно указать пол и дату рождения в профиле — оба поля необязательны. Если дата сохранена и на устройстве разрешены push-уведомления, в день рождения придёт персональное поздравление от ЕНОТа. Мастер и администратор эти поля не видят.

В программе лояльности 1 балл даёт 1 ₽ скидки, но баллы не являются деньгами и не переводятся и не выводятся. После подтверждённой денежной оплаты ремонта начисляется 10%, заказного изделия — 5%. Ранее начисленные игровые баллы остаются на бонусных балансах клиентов; игровые награды больше не выдаются. При выдаче ремонта мастер или администратор может выбрать списание баллов: не больше доступного остатка и 30% стоимости строк «Услуга». Запчасти, товары и изделия бонусами не оплачиваются; профилактическая работа подходит, если добавлена в заказ как услуга.

В программе лояльности клиенту выдаются три личных одноразовых кода приглашения сроком на шесть месяцев. Код можно указать при регистрации в Android или Web; после первого завершённого и оплаченного ремонта нового клиента по 250 бонусных баллов начисляется и ему, и пригласившему. Регистрация сама по себе награду не выдаёт. В карточке видны сроки и статусы кодов, а поделиться можно каждым ещё доступным кодом. Баллы остаются личными, не переводятся и не обналичиваются.

Раздел «Рукоделия» доступен с главной клиента и из управления администратора. Клиенты просматривают опубликованные готовые изделия с фото и ценой либо отправляют заявку на заказное изделие; администратор добавляет материалы, меняет цены, публикацию и фото, а также обрабатывает заявки. В каждой заявке есть отдельный чат клиента с администратором: можно отправлять текст и фотографии, а после статуса «В работе» переписка автоматически открывается внутри карточки заказа. Фото доступны только участникам чата этой заявки. Перед завершением администратор назначает активного мастера и цену; при завершении автоматически создаются чек и сервисный номер, а зарплата мастера рассчитывается по его сохранённой индивидуальной ставке. Заказные изделия бонусами не оплачиваются: администратор может списать бонусы только за услуги ремонта, максимум 30% их стоимости. Онлайн-оплата не подключена: заявка остаётся запросом, а подтверждение оплаты фиксирует уже полученный платёж.

Раздел «О компании» доступен клиентам и мастерам из дополнительных ссылок профиля, а администраторам — из управления сервисом. Администратор может изменить общие сведения о компании в Android-приложении или веб-панели; клиенты и мастера видят описание, историю, услуги, контакты, график, соцсети, реквизиты и добавленные ссылки на фото и видео.

В карточке заказа клиент и назначенный мастер могут открыть сохранённый чат. Мастер может передать вопрос администратору; запрос появится в разделе управления, администратор подключится к беседе и сможет ответить. Чат клиента с администратором проверяет новые сообщения каждые 3 секунды, список клиентских чатов администратора — каждые 5 секунд; время каждого сообщения показывается по часовому поясу устройства. Android принимает push о сообщениях и запросах помощи, изменениях заказа (включая назначение, статус, состав, расчёт, фото и отзывы), первой публикации новости и поздравлениях с днём рождения. Публикация акции или розыгрыша уведомляет клиентов при начале срока проведения; статусы «Готов к выдаче» и успешная выдача техники получают отдельные понятные уведомления. Сервер уведомляет участников заказа, кроме автора действия; новости и предложения рассылаются клиентам. Для обычных уведомлений используется фирменный звук «Мягкая искра», а для победы в розыгрыше — отдельный праздничный вариант. Приложение создаёт системные каналы `repair_updates_soft_spark` и `repair_winner_soft_spark`; сервер отправляет победителям уведомление с Android channel ID `repair_winner_soft_spark`, остальные сообщения идут в `repair_updates_soft_spark`. Пользователь может изменить звук или отключить уведомления каждого канала в настройках Android. Для доставки нужны Firebase-настройки, зарегистрированный токен устройства и разрешение на уведомления.

Приложение проверяет наличие новой версии на сайте при открытии и возвращении на экран. Если в панели администратора загружен APK с более высоким номером сборки, приложение показывает предложение обновиться. После нажатия оно скачивает APK по HTTPS, сверяет SHA-256, package name и версию, затем открывает системный установщик Android. Если потребуется, пользователь разрешает установку APK из ЕНОТ СЕРВИС в настройках устройства. Android отдельно проверяет подпись приложения и требует подтвердить установку; обновление не устанавливается скрытно. Администратор указывает в панели название и номер сборки, совпадающие с загруженным APK. Старые установленные версии без этой проверки сначала нужно обновить обычным способом.

Удаление строк заказа, онлайн-оплата и публикация APK в Google Play в текущую версию не входят.

Русская политика конфиденциальности доступна по адресу `https://xn----dtbhbq0ahshee.xn--p1ai/privacy-policy.html`. Ссылка открывается из экранов входа, регистрации и профиля Android-приложения; перед каждым релизом сверяйте текст политики и публичную страницу сайта.

Нативное приложение на Kotlin и Jetpack Compose для ремонта компьютеров, ноутбуков, телефонов и планшетов. Название приложения — ЕНОТ СЕРВИС. Идентификатор пакета `ru.utp.servise` сохранён для совместимости обновлений.

## Реализованные сценарии

- Отдельные порталы входа клиента, мастера и администратора. Публичная регистрация создаёт только клиента и требует корректный номер телефона; выбрать себе роль сотрудника нельзя. Если клиент вошёл через VK ID или восстановил старый аккаунт без номера, личный кабинет остаётся закрытым до сохранения телефона.
- На экране входа клиент, мастер или администратор может запросить письмо для восстановления пароля. Одноразовая ссылка открывает адаптивный веб-экран задания нового пароля.
- На экранах входа и регистрации клиента доступен вход через бота МАКС: приложение получает одноразовую ссылку `https://max.ru/<botName>?start=<payload>`, открывает её, а затем каждые две секунды проверяет подтверждение. В чате бот просит поделиться контактом; сервер проверяет подпись контакта и находит или создаёт клиента по номеру телефона. При регистрации бот отправляет «Спасибо что выбрали нас!». Пароль не нужен, новый аккаунт создаётся только в роли клиента, а код приглашения применяется при создании. Сотрудники по-прежнему входят по почте и паролю. Вход через Яндекс ID удалён.
- Клиент с аккаунтом MAX может в профиле добавить резервную почту: запросить код, подтвердить адрес и задать пароль. Только после подтверждения можно войти по почте и паролю; вход через MAX продолжает работать.
- Если настроены `VK_ID_APP_ID` и `VK_ID_CLIENT_SECRET`, на экране входа доступен VK ID. Приложение запрашивает email, отправляет полученный VK access token в `POST /api/auth/vk`, а сервер сам проверяет его у VK ID. Новый аккаунт создаётся только для клиента; привязка к существующей почте требует её пароль. Существующие способы входа не заменяются.
- Клиент создаёт заявку, видит только собственные заказы и историю, может отменить только новую заявку и оставить один отзыв после завершения ремонта.
- В профиле клиент может начать удаление аккаунта прямо в Android-приложении. Перед подтверждением показывается предупреждение об удалении заявок, заказов, переписок, фото и бонусов; после успеха очищается локальная корзина, а при временной ошибке очистки сессию можно использовать для повторной попытки.
- Отдельный экран «Магазин товаров» доступен клиенту с главной страницы и использует только активные товары каталога, отдельно от услуг ремонта, запчастей и заявок. Клиент собирает корзину и отправляет отдельный заказ без онлайн-оплаты; в магазине видны его статусы. Администратор открывает «Заказы магазина» из управления, проверяет наличие до подтверждения (в этот момент списывается учтённый остаток), а затем отмечает заказ выданным или отменяет его; при отмене подтверждённого заказа остаток возвращается. Оплата и получение согласуются отдельно от приложения.
- После завершения ремонта клиент видит в карточке заказа поздравление енота, краткий итог работ и условия выданной гарантии. Кнопка открывает существующую форму отзыва; повторный отзыв не предлагается. Рядом есть отдельная кнопка «Отправить чаевые»; пока она сообщает, что приём платежей станет доступен после регистрации и настройки ЮMoney, и не запускает оплату.
- Игровая функция и её API удалены из Android и Web. Первая новая версия очищает прежний WebView-кэш и локальные игровые отметки; аккаунты, корзина и уже начисленные бонусные баллы сохраняются. Игровые таблицы удаляются миграцией базы данных, а записи `GAME_REWARD` в журнале бонусов остаются.
- Нижняя панель клиента содержит «Главная», «Ремонты», «Магазин», «Бонусы» и «Профиль»; панель мастера — «Заказы», «Каталог», «Зарплата» и «Профиль»; закупки и администратор используют короткие панели из трёх и четырёх пунктов соответственно. История завершённых заявок доступна из фильтра списка ремонтов; дополнительные клиентские и мастерские экраны открываются из профиля, а администраторские операции собраны в шесть групп управления. Текущая роль сохраняет выделение профиля на дополнительных экранах.
- В новой заявке клиент может указать марку, модель и серийный номер техники, добавить фото и выбрать желаемое время. Время предварительное: сервис подтверждает его после проверки расписания; выбранное фото привязывается к созданной заявке.
- В назначенной заявке мастер формирует начальную смету из активного каталога и передаёт администратору на подтверждение. Клиент видит версию, диагностику, состав и итоговую сумму, но не согласует и не отклоняет смету в приложении. Администратор подтверждает смету или возвращает её мастеру; только после подтверждения списывается склад и разрешается начать ремонт. Во время ремонта мастер может самостоятельно добавлять фактически выполненные услуги и запчасти в черновик акта без предварительного согласования. Отправленный акт проверяет только администратор: отмечает ненужные строки и подтверждает оставшиеся, не запрашивая повторного решения мастера. До подтверждения акта не меняются склад, чек или зарплата; после подтверждения склад пересчитывается по разнице, а итоговые строки используются для чека и расчёта мастера. Новые заявки нельзя перевести в «Готов к выдаче» или выдать без подтверждённого акта. Для старых заявок мастер также создаёт акт; при наличии начальной сметы дополнительные изменения проходят через новую смету на подтверждение.
- В акте мастер открывает быстрый каталог с поиском по названию и описанию, фильтрами по типу позиции, избранным и восемью последними добавленными позициями. Списки сохраняются локально для учётной записи на этом устройстве и не синхронизируются с Web. Добавление по-прежнему создаёт только черновую строку; одобрение администратора остаётся обязательным для изменения чека и склада.
- Клиент может независимо включать уведомления о ходе ремонта через Telegram и MAX в профиле. Каждая привязка подтверждается одноразовой ссылкой и может быть отключена отдельно; для MAX серверу нужен подключённый токен бота и вебхук.
- В карточке каждой заявки показывается линейный штрихкод Code 128 с сервисным номером. Это только идентификатор заявки; QR-код для выдачи не используется.
- Клиент и сотрудники видят плановую дату готовности и историю переносов с пояснением и автором. Администратор может изменить или снять срок из карточки; сервер фиксирует каждое реальное изменение и отправляет клиенту push-уведомление. Для доставки push нужны Firebase-настройки и разрешение на уведомления.
- Администратор создаёт заявку от имени сервиса для существующего или нового клиента и выбирает место ремонта: у клиента или в сервисном центре. Выбор сохраняется отдельно от контактного адреса клиента и показывается в карточке заявки. Для нового клиента указываются имя и телефон; электронная почта необязательна. Если почты нет, API создаёт отдельный логин и временный пароль, но не показывает пароль администратору. Администратор получает ссылку MAX, закреплённую за этой записью клиента; бот отправляет логин и временный пароль только после того, как клиент откроет ссылку и подтвердит свой номер телефона в MAX. Клиент обязан сменить временный пароль при первом входе. Для клиента с электронной почтой остаётся прежняя выдача временного пароля администратору. Если создание заявки не удалось после регистрации, аккаунт остаётся в базе и заявку можно повторить для этого клиента.
- Незавершённые заявки, в том числе перенесённые на другой срок, остаются в активных до полного завершения ремонта или отмены независимо от даты создания. Выполненные и отменённые заявки переходят в архив на следующий московский календарный день после последнего изменения; архив доступен отдельной вкладкой в списках клиента, мастера и администратора, записи и статусы сохраняются.
- Видео- и GIF-заставка с приветствием отключена: при запуске приложение сразу открывает обычный экран. Приветствие енота в карточке завершённого ремонта сохранено.
- В карточке заявки услуги и запчасти ограничены выбранным типом устройства: ПК, ноутбук, телефон или планшет. Администратор задаёт подходящие типы для каждой позиции каталога; товары магазина остаются отдельными.
- Мастер видит только назначенные ему заказы. При ремонте в сервисе он отдельно отмечает завершение работ; статус «Готов к выдаче», оплата и выдача остаются за администратором. При выезде мастер сам согласует ремонт с клиентом и фиксирует оплату наличными или переводом; если ремонт на месте невозможен, с согласия клиента оформляет акт состояния и комплектности с фото/видео и передаёт устройство в сервис. В сервисном центре бонусы списываются только с услуг (1 балл = 1 ₽, максимум 30% стоимости услуг и доступного остатка), не с запчастей, диагностики или километража. После оплаты сервер закрывает заказ и создаёт гарантийный талон; клиентский QR-код и сканер для выдачи не нужны.
- В карточке заказа доступны упрощённый акт приёма-передачи с одним описанием состояния и одним фото или видео, серийным номером, комплектностью и примечаниями, заказ-наряд и выданный гарантийный талон. Перед выдачей сервер требует сохранённый акт и одно медиа; прежние акты и прикреплённые фото остаются доступными.

## Карточка мастера

Мастер открывает свою анкету из профиля и может редактировать ФИО, телефон, домашний адрес, фото
и стаж. Администратор может просматривать домашний адрес в карточке мастера. Клиенты видят
публичные данные карточки из заказа, но домашний адрес API им не возвращает.

- Мастер видит личную зарплату за день, неделю и месяц; администратор — суммы и индивидуальные ставки всех мастеров. Администратор задаёт процент мастера в Web-разделе «Администрирование → Сотрудники»; по умолчанию действует 75%. Начисление рассчитывается только от стоимости услуг завершённого ремонта, запчасти и товары не учитываются. Применённая ставка сохраняется в начислении, поэтому новая ставка влияет на будущие завершённые заказы, не пересчитывая уже сохранённые суммы; дата начисления — момент завершения заказа.
- Администратор просматривает все заказы, назначает активного мастера, управляет рабочими учётными записями и видит отзывы. В разделе «Управление → Сотрудники → Изменить» администратор может задать индивидуальный процент оплаты каждого мастера (0–100%, по умолчанию 75%). Ставка применяется только к услугам в новых начислениях; запчасти и товары не учитываются, а уже сохранённые начисления не пересчитываются.
- В разделе администратора «Управление» доступны обзор сервиса за 30 дней, недельное расписание выбранного клиентом времени с загрузкой мастеров и закупочная сводка. Рекомендованное количество к заказу доводит остаток до минимального порога; детали из подтверждённых смет уже списаны со склада и показываются отдельно. Администратор также может отметить заявку как срочную; это приоритет внимания, а не отдельная гарантия срока.
- Клиент может открыть отдельный чат с администратором с главного экрана. Администратор получает список клиентских бесед и отвечает из Android-раздела «Управление»; этот чат не зависит от заявки и сохраняет историю сообщений.
- В разделе «База клиентов» администратор ищет клиентов по имени, почте или телефону и редактирует эти контактные данные. Удаление мастера отключает его учётную запись и завершает сессии, но сохраняет историю; при незавершённых назначенных заказах удаление блокируется до их переназначения или завершения.
- Android-раздел «Управление» позволяет создавать новости с фото или видео, публиковать акции и розыгрыши, выбирать победителей после окончания розыгрыша, публиковать результаты с начислением предусмотренных баллов, а также создавать баннеры с фото или видео, редактировать, включать и отключать их. История баллов доступна только для просмотра. Веб-панель по-прежнему нужна для поиска и сроков заказов и сервисных документов; раздел «О компании» доступен для редактирования и в Android, и в веб-панели.
- Пароли хранятся как scrypt-хеши, токены сессий — только в виде хеша на сервере; токен на Android хранится зашифрованным Android Keystore.
- Все существенные действия проверяются сервером, а не только скрытием экранов. История статусов хранится в базе.

## Каталог, магазин и бонус ко дню рождения

Карточка товара в Android-магазине показывает описание и до четырёх фотографий, синхронизированных
с общим каталогом API. Администратор управляет товарами из каталога; очередь ожидающих подтверждения
магазинных заказов вынесена в отдельный раздел «Подтверждение заказов магазина», а все заказы доступны
отдельным фильтром. Администратор может редактировать, отключать и повторно включать все позиции
каталога. Начисление бонуса ко дню рождения составляет 250 баллов один раз за год и не зависит от
разрешения на push-уведомления.

Администратор может окончательно удалить услугу, запчасть или товар после подтверждения. Для товара
и запчасти сначала требуется указать остаток 0; удалить позицию, используемую в незавершённом ремонте,
ожидающей смете или ожидающем/подтверждённом заказе магазина, нельзя. Завершённые и отменённые заказы
остаются в истории с исходным названием и ценой.

## Сезонное оформление

Приложение получает активную палитру через публичный API и обновляет её примерно раз в минуту.
Администратор открывает отдельную вкладку «Сезоны» и включает один из четырёх вариантов: весну,
лето, осень или зиму; переключатель активного варианта также отключает оформление. Выбор не зависит
от календарной даты и сохраняется на сервере до следующего изменения, одновременно обновляя Web и
Android. При включённой теме её иллюстрация становится общим полноэкранным фоном под
всеми разделами, включая вход; поверх всего экрана ненавязчиво движутся лепестки весной, световые
блики летом, листья осенью или снег зимой. В осенней теме поверх листьев раз в час включается
дождь длительностью 30 минут и повторяется раз в час. Карточки и поля остаются на своих контрастных поверхностях.
Иллюстрации посвящены ремонту компьютеров и ноутбуков: в них есть ноутбуки, компьютерные платы и
инструменты, без стиральных машин и другой бытовой техники.

## Сборка

```bash
./gradlew :app:assembleDebug --no-daemon --max-workers=2
```

Для обычной сборки требуются JDK 17, Android SDK 36 и HTTPS-переменная `UTP_API_BASE_URL`. APK от `assembleDebug` для разработки не предназначен для публикации. Эмулятор и физическое устройство в среде Amazi недоступны.

Игровых экранов и игровых маршрутов в Android-приложении нет.

Вход через МАКС не требует отдельных переменных в Android-сборке: приложение использует те же HTTPS-адреса `/auth/max/config`, `/auth/max/login` и `/auth/max/login/poll` и открывает чат бота через системный браузер или приложение МАКС. Ссылку и подтверждение формирует сервер, поэтому `MAX_BOT_TOKEN` и секреты вебхука остаются только на API.

### Подписанная сборка для RuStore

Release-вариант подписывается только при заданных переменных `UTP_RELEASE_KEYSTORE_PATH`, `UTP_RELEASE_STORE_PASSWORD`, `UTP_RELEASE_KEY_ALIAS` и `UTP_RELEASE_KEY_PASSWORD`. Задайте их в среде сборки, а `UTP_API_BASE_URL` направьте на HTTPS production API, затем выполните:

```bash
./gradlew :app:assembleRelease --no-daemon --max-workers=2
```

Готовый APK находится в `app/build/outputs/apk/release/`. Файл keystore и пароли — постоянные данные подписи: храните резервную копию в защищённом месте и применяйте ту же подпись при последующих обновлениях. Не добавляйте keystore или пароли в Git. До публикации приложения проверьте, что production API развёрнут и доступен; сборка Android сама API не публикует.

VK ID Android использует официальный SDK `com.vk.id:vkid:2.7.3` из репозитория VK Nexus. В debug-сборке вход через VK можно включать локальными `VK_ID_APP_ID` и `VK_ID_CLIENT_SECRET`. В release эти manifest placeholders и `VK_ID_APP_ID` намеренно очищаются: client secret можно извлечь из распространяемого APK, поэтому вход через VK ID в релизе отключён. Остальные способы входа остаются доступны. Не включайте VK ID в release, пока авторизация не будет переведена на схему без секрета в мобильном клиенте.

Production API доступен на `https://merge.app.amazi.pro`; `/health` отвечает HTTP 200. APK от `assembleDebug` предназначен только для разработки и не годится для публикации.

Чтобы включить push в Android-сборке, задайте `UTP_FIREBASE_ANDROID_CONFIG_JSON` с конфигурацией Firebase Android-приложения `ru.utp.servise`. На API для отправки уведомлений нужна отдельная серверная переменная `FCM_SERVICE_ACCOUNT_JSON`. Если Firebase-конфигурация не задана, Android APK всё равно собирается, но push-доставка недоступна.
