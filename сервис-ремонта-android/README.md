# UTP Servise — Android

В карточке заказа показываются услуги и запчасти из общего каталога с количеством, ценой и суммой. Администратор может пополнять прайс, редактировать и отключать позиции; мастер выбирает активные позиции только для назначенных ему заказов. Сервер фиксирует цену при добавлении, а уже оформленные строки сохраняются при изменении прайса. В каталоге запчастей администратор задаёт и корректирует остаток, мастер видит его при выборе, а позиция с нулевым остатком недоступна для добавления. При добавлении запчасти к заказу остаток списывается на сервере; при удалении строки или отмене заявки возвращается. Для старых позиций без записанного начального остатка сначала внесите фактическое количество.

Администратор редактирует чек каждого завершённого заказа отдельно из его карточки: меняет количества услуг и запчастей, добавляет одну позицию «Свободная продажа» (товар или услуга, название, количество и цена) и пересохраняет неоплаченный чек. Сервер одновременно обновляет состав заказа, бонусную скидку и расчёт мастера; оплаченный чек нельзя менять. Список заявок остаётся общим, а состав и чек управляются в отдельном заказе.

На клиентской главной отображаются опубликованные новости. Администратор может создавать черновики, редактировать новости, публиковать и снимать их с публикации. Клиенты и мастера не получают черновики.

Администратор может задать для новости начало и окончание публикации по местному времени устройства и отметить её приоритетной. Сервер показывает новость обычным пользователям только внутри заданного интервала и возвращает приоритетные новости первыми; административный список сохраняет доступ к черновикам и публикациям вне срока.

В настройках профиля доступны темы «Как в системе», светлая и тёмная. Выбор хранится на устройстве и применяется после перезапуска приложения.

Раздел «Рукоделия» доступен с главной клиента и из управления администратора. Клиенты просматривают опубликованные готовые изделия с фото и ценой либо отправляют заявку на заказное изделие; администратор добавляет материалы, меняет цены, публикацию и фото, а также обрабатывает заявки. Заказы на рукоделия — запросы для связи с администратором, не онлайн-покупка и не оплата.

Раздел «О компании» доступен клиентам с главной, мастерам из нижнего меню и администраторам в управлении сервисом. Администратор может изменить общие сведения о компании в Android-приложении или веб-панели; клиенты и мастера видят описание, историю, услуги, контакты, график, соцсети, реквизиты и добавленные ссылки на фото и видео.

В карточке заказа клиент и назначенный мастер могут открыть сохранённый чат. Мастер может передать вопрос администратору; запрос появится в разделе управления, администратор подключится к беседе и сможет ответить. Чат клиента с администратором проверяет новые сообщения каждые 3 секунды, список клиентских чатов администратора — каждые 5 секунд; время каждого сообщения показывается по часовому поясу устройства. Android принимает push о сообщениях и запросах помощи, изменениях заказа (включая назначение, статус, состав, расчёт, фото и отзывы) и первой публикации новости. Сервер уведомляет участников заказа, кроме автора действия; новости рассылаются клиентам. Для доставки нужны Firebase-настройки, зарегистрированный токен устройства и разрешение на уведомления.

Удаление строк заказа, онлайн-оплата и публикация APK в Google Play в текущую версию не входят.

Нативное приложение на Kotlin и Jetpack Compose для ремонта компьютеров, ноутбуков, телефонов и планшетов. Логотип и название UTP Servise размещены в приложении.

## Реализованные сценарии

- Отдельные порталы входа клиента, мастера и администратора. Публичная регистрация создаёт только клиента; выбрать себе роль сотрудника нельзя.
- На экране входа клиент, мастер или администратор может запросить письмо для восстановления пароля. Одноразовая ссылка открывает адаптивный веб-экран задания нового пароля.
- Клиент создаёт заявку, видит только собственные заказы и историю, может отменить только новую заявку и оставить один отзыв после завершения ремонта.
- По умолчанию при запуске показывается короткая пропускаемая приветственная анимация с енотом.
- В «Профиль → Внешний вид» можно выбрать динамичную анимацию, спокойное появление, подъём снизу, увеличение, поворот или отключить заставку. Выбор хранится на устройстве и действует при следующем запуске приложения.
- Мастер видит только назначенные ему заказы, начинает и завершает ремонт по разрешённой последовательности статусов.
- Мастер видит личную зарплату за день, неделю и месяц; администратор — суммы всех мастеров. Начисление составляет 75% стоимости услуг завершённого ремонта, запчасти не входят; дата начисления — момент завершения заказа.
- Администратор просматривает все заказы, назначает активного мастера, управляет рабочими учётными записями и видит отзывы.
- Клиент может открыть отдельный чат с администратором с главного экрана. Администратор получает список клиентских бесед и отвечает из Android-раздела «Управление»; этот чат не зависит от заявки и сохраняет историю сообщений.
- В разделе «База клиентов» администратор ищет клиентов по имени, почте или телефону и редактирует эти контактные данные. Удаление мастера отключает его учётную запись и завершает сессии, но сохраняет историю; при незавершённых назначенных заказах удаление блокируется до их переназначения или завершения.
- Администраторский веб-раздел дополнительно предоставляет поиск и сроки заказов, сервисные документы, расписание и приоритет новостей, модерацию отзывов, баннеры, баланс клиентов и историю бонусов. Раздел «О компании» доступен для редактирования и в веб-панели.
- Пароли хранятся как scrypt-хеши, токены сессий — только в виде хеша на сервере; токен на Android хранится зашифрованным Android Keystore.
- Все существенные действия проверяются сервером, а не только скрытием экранов. История статусов хранится в базе.

## Сборка

```bash
./gradlew :app:assembleDebug --no-daemon --max-workers=2
```

Для обычной сборки требуются JDK 17, Android SDK 36 и переменная `UTP_API_BASE_URL` с HTTPS-адресом API. APK от `assembleDebug` для разработки не предназначен для публикации. Эмулятор и физическое устройство в среде Amazi недоступны.

### Подписанная сборка для RuStore

Release-вариант подписывается только при заданных переменных `UTP_RELEASE_KEYSTORE_PATH`, `UTP_RELEASE_STORE_PASSWORD`, `UTP_RELEASE_KEY_ALIAS` и `UTP_RELEASE_KEY_PASSWORD`. Задайте их в среде сборки, а `UTP_API_BASE_URL` направьте на HTTPS production API, затем выполните:

```bash
./gradlew :app:assembleRelease --no-daemon --max-workers=2
```

Готовый APK находится в `app/build/outputs/apk/release/`. Файл keystore и пароли — постоянные данные подписи: храните резервную копию в защищённом месте и применяйте ту же подпись при последующих обновлениях. Не добавляйте keystore или пароли в Git. До публикации приложения проверьте, что production API развёрнут и доступен; сборка Android сама API не публикует.

На момент последней release-сборки корень production API отвечал HTTP 404. Поэтому APK подписан и годится для проверки загрузки в консоль RuStore, но приложение не готово к использованию клиентами до отдельной публикации и проверки API.

Чтобы включить push в Android-сборке, задайте `UTP_FIREBASE_ANDROID_CONFIG_JSON` с конфигурацией Firebase Android-приложения `ru.utp.servise`. На API для отправки уведомлений нужна отдельная серверная переменная `FCM_SERVICE_ACCOUNT_JSON`. Если Firebase-конфигурация не задана, Android APK всё равно собирается, но push-доставка недоступна.

## Границы текущей версии

API и база работают в среде разработки; миграции ролей, заказов, истории, отзывов, каталога и push-токенов применены. Начальная административная учётная запись создана, одноразовые bootstrap-переменные удалены. Платёжная интеграция не подключена. Для push обработчики на Android и серверные события уже есть, но конфигурация Firebase Android-клиента и серверный ключ пока не заданы, поэтому доставку уведомлений проверить нельзя. Публикация API или приложения в Google Play не выполнялась.
