# Android APK distribution

- Administrators manage the Android release from **Администрирование → Android-приложение — APK** in the Web application. The API reads the package, `versionName`, and integer `versionCode` directly from the uploaded APK manifest; the package must be `ru.utp.servise`, and the version code must be higher than the currently managed release.
- The API accepts an Android APK up to 100 MiB only from an authenticated `ADMIN`. It stores file bytes in Amazi project object storage and keeps the object ID, size, SHA-256, version metadata, upload time, and any pending cleanup IDs in the `app_settings` row with key `android_app_apk`.
- `GET /api/android-app` exposes the active file's version and checksum with `Cache-Control: no-store`. `GET /api/android-app/download` redirects to an expiring HTTPS download URL for the active object. Before the first managed upload, it redirects to the existing Web APK asset; after deletion it returns 404 instead of restoring that fallback.
- Uploading a replacement activates the new object before removing the previous object. If object cleanup temporarily fails, its ID remains recorded and an administrator can retry cleanup from the panel. Deleting disables the public download link and removes the active object from project storage.
- Android builds containing the updater check the API when the app opens or returns to the foreground. If the managed APK has a higher version code, the app offers **Обновить** or **Позже**. After confirmation, it downloads the APK over HTTPS, checks SHA-256, package name, version name, and version code, then opens the Android installer. Android separately enforces package-signature compatibility and asks the device owner to approve installation. The app never installs without that system confirmation.
- The first updater-enabled APK must be installed once through the existing distribution channel (or from the site) before older installed builds can offer future updates; old APKs cannot run code that was not included in them. The app does not upload releases to RuStore or another store.
- Uploading or replacing an APK does not send a push notification. Once a managed APK is available, an administrator can explicitly start the separate “Сообщить всем об обновлении” action. It targets active accounts with registered push-device tokens; delivery depends on Firebase configuration and device notification permissions. Opening the notification starts the app, which checks for the current release.
- The Web Android download button resolves the current state and uses the permanent API download route, so an uploaded APK replaces the former download without changing the Web page or its link.
